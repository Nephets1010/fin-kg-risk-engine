# ADR-0004：风险评分模型 —— 规则基线与 GNN 分离

- **状态**：已接受
- **日期**：2026-10-29

## 背景

风控评分面临一个经典矛盾：

- 风控分析师需要**可解释** —— 一个风险分必须能说清楚「为什么是这个分」。
- 模型效果需要**非线性** —— 线性模型表达不了「高担保 + 多层链条 + 近期负面」的联合效应。

GNN 能捕捉这种联合效应，但它的输出是黑箱。如果把 GNN 的输出直接当作风险分，风控团队会拒绝使用。

同时存在一个数据现实：**风险标注极度稀缺**。一家机构一年可能只有几百个确认的风险案例，其中真正可用于训练的、覆盖全部风险类型的可能只有几十个。

## 决策

### 1. 基准分与模型分**并行输出，不融合**

系统维护两个独立的分数：

| 分数 | 来源 | 可解释性 | 用途 |
|---|---|---|---|
| **基准分** `baseline-1.0.0` | 10 个加权指标的算术平均 | 完全可解释 | 预警阈值判定、风控人工复核 |
| **模型分** | GraphSAGE 节点分类 | 弱（需 SHAP/贡献边辅助） | 排序辅助、模型效果验证 |

**为什么不融合成一个分**：融合后的数字无法解释。「这个主体风险 72 分」若来自基线与 GNN 的加权，用户无法回答「是哪个因素导致的」。分开之后，每个分数的来源单一、语义清晰。

### 2. 基准分的数学定义

```
score = Σ(sub_score_i × weight_i) / Σ(weight_i)
```

分母是**实际权重和**而非固定 1.0。这样即使指标目录新增或暂时缺失，输出仍在同一条 0~100 尺度上，不会因为分母变化而跳变。`RiskScorer.breakdown` 同时输出 `coverage`（数据覆盖率），让分析员知道这个分数建立在多少数据上。

### 3. 指标是**版本化**的声明

```python
IndicatorSpec(
    id="IND-GUA-001",
    name="对外担保余额占注册资本比",
    version="1.1.0",
    direction=HIGHER_IS_RISKIER,
    weight=0.20,
    thresholds=((0, 0), (0.5, 25), (1.0, 50), (2.0, 80), (5.0, 100)),
    measurement_cypher="...",
)
```

每个指标记录 `version`，每条预警记录贡献指标的版本号。因此「今天的分」和「半年前的分」可以逐指标对齐比较。

### 4. 指标使用**比率**而非绝对金额

`对外担保余额` 若用绝对金额，5000 万担保对注册资本 1 亿的公司是严重风险，对注册资本 100 亿的公司微不足道。改用 `担保余额 / 注册资本` 后，跨主体可比。同理 `强制执行金额占注册资本比`。

所有金额统一为 **万元**（工商登记的原始单位），保证比率两侧同量纲。

### 5. GNN 用 NumPy 自实现，而非直接依赖 PyG

GraphSAGE 的核心是「邻居均值聚合 + 两层权重 + ReLU + 逻辑回归」。用 NumPy 完整实现（180 行，含前向、反向、类别加权损失）带来三个好处：

- CI 不需要下载数百 MB 的 torch/torch-geometric，测试在 10 秒内跑完。
- 训练循环被单元测试真实覆盖（`test_training_reduces_loss`），而不是只测一个包装层。
- 推理环境可以不带 torch。

`[gnn]` extra 保留了 PyTorch 生态的接入位。

### 6. 弱监督是默认的标签来源

`WeakSupervisor` 从规则引擎反推标签：触发 major/critical 规则的实体记为正样本。这让模型能在**零人工标注**的情况下先跑通链路，再用少量人工标注替换。公开数据集（如 CN-DBpedia 派生标注）与人工 CSV 通过同一 `LabelStore` 接口接入。

### 7. 评估用 F1 与 ROC-AUC，不用 accuracy

正样本占比通常低于 5%，accuracy 在这种分布下没有意义。`GNNTrainer` 同时输出 precision / recall / F1 / ROC-AUC，并在验证集样本过少或缺少正样本时**明确写入 warnings**，而不是给出一个漂亮但不可信的数字。

## 后果

**正面**

- 基准分完全可解释：每条预警都能列出「哪些指标贡献了多少分」。
- 基准与模型分可独立验证：模型分优于基准分时，收益是量化且可复现的。
- 单元测试覆盖训练循环本身。
- 分数可跨时间比较（指标版本化）。

**负面 / 代价**

- 两个分数需要分别向用户解释，产品设计上要更小心。
- 指标目录需要人工维护权重与阈值，权重之和必须为 1（有测试守护）。
- NumPy 的 GraphSAGE 只支持全批量梯度下降，不支持 mini-batch 与大规模图采样；生产规模下需换 PyG 实现。

## 验证方式

- `tests/unit/test_risk.py::TestRiskScorer`：加权平均、缺失读数导致的覆盖率下降。
- `tests/unit/test_domain.py::TestIndicators`：权重和为 1、阈值单调、两个方向的打分语义。
- `tests/unit/test_risk.py::TestGNN`：前向形状、训练收敛、概率范围、模型存取往返。
- `tests/unit/test_risk.py`：precision/recall/F1 与 ROC-AUC 的已知答案用例。

## 撤销条件

当业务方明确要求「单一融合风险分」且接受其不可解释性时，可以引入 `FusionSpec` 把两个分数按固定权重融合，同时保留分解视图。
